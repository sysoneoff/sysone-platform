# SysOne V4.4 Phase 2 — readiness and staging checklist

Scope: `v4.4-development` branch only. Do not merge to the live branch or deploy to production without explicit approval.

## Evidence

- GitHub Actions: `npm ci`, `npm run typecheck`, `npm run verify`, `npm test`, `npm run build`.
- A passing build is not a runtime or Cloudflare D1 integration test.
- Phase 2 admin endpoints are authenticated with `isAdminAuthenticated`; PATCH cancellation additionally checks request origin with `isSafeAdminMutation`.
- Orders can be cancelled only while `PENDING`, without `paid_at`, without `payment_reference`, and without an associated entitlement. The database performs the guard and update in one SQL statement.
- Customer 360 is read-only; refund, payment confirmation, and entitlement issuance are deliberately outside the Phase 2 manager.

## Separate test environment (operator runbook)

1. Create a distinct nonproduction Cloudflare Worker and **separate D1 database**. Do not reuse production D1, R2, API keys, auth secret, or payment provider credentials.
2. Configure a dedicated staging hostname / route that does not match the production domain. Disable any direct branch-to-production deployment integration.
3. Provision the staging D1 schema from `database/schema.sql` plus any repository migrations required by the current V4 deployment. Back up before applying changes.
4. Use dummy customer accounts, orders, products, entitlements, and tickets; do not copy real customer PII.
5. Verify unauthenticated endpoints `/api/admin/v4/analytics`, `/api/admin/v4/customers`, `/api/admin/v4/orders` return 401.
6. Log into the staging Owner Tool and check dashboard counts, 14-day chart, recent orders, Customer 360, searching, paging, and CSV export.
7. Verify `GET /api/admin/v4/orders/[id]` details. Cancel a synthetic unpaid order and confirm 200 and `CANCELLED`, an audit entry, and no new entitlement.
8. Attempt cancellation of synthetic PAID, payment-referenced, and entitlement-linked orders; each must yield 409 with no data change. Attempt a cross-origin PATCH and expect 403.
9. Ensure CSV export escapes formulas and only contains the current authorized page. Check 0-record screens and mobile overflow.
10. Confirm GitHub Actions are green for the exact commit and no production deploy event occurred. Keep production untouched until a separate explicit release decision.

## Important operational notes

- `paidRevenueByCurrency` is an **order-ledger aggregate**, not independently verified settlement data. It is not a bank reconciliation report.
- Cancellation audit writing uses the existing `writeAdminAudit` helper, which logs errors rather than failing the cancellation. Monitor audit logs and consider a transactional outbox before production financial workflows.
- Node's built-in `node:sqlite` test is an integration check for SQL guards against an in-memory SQLite fixture; it does **not** establish live Cloudflare D1 connectivity.
